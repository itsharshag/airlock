How it works

Each request gets one of three answers.

The page never holds a key. It calls window.near, and Airlock decides who signs.

ALLOW

The agent key signs

The request fits the agent's NEAR function-call key. That key calls one method on one contract and cannot move NEAR.

signer: agent key
ASK YOU

Only you can approve

The request moves funds, or the receiver is new, barely used, or changed its contract this week.

signer: your key, after you click
BLOCK

Nobody signs

The receiver imitates a known account or is on the blocklist, the request adds a full access key, or the site's code failed its pin.

signer: none
Why a browser

An extension cannot do this job.

Chrome gives extensions no access to response bodies, and an agent that controls the browser can click any button an extension draws.

Try it

Run it against the hosted demo sites.

You need Node 20 and macOS or Linux. The scripts create a fresh testnet account for you.

$ git clone https://github.com/itsharshag/airlock && cd airlock && npm install
$ node scripts/make-account.js    # testnet account from the faucet
$ node scripts/add-agent-key.js   # the agent's scoped key, on chain
$ node scripts/make-payee.js
$ T=https://airlock-tipjar.itsharshag.com
$ AIRLOCK_START_URL=$T AIRLOCK_PINS=$T npm start
# Sign the guestbook, tip 0.1 NEAR, then open airlock-news.itsharshag.com
# Open $T/__attacker/swap?on=1 to swap app.js in your browser only
